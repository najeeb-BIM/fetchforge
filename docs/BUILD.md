# Developer build guide

## Tool versions (verified 2026-10-26)

- Rust: current stable (tested with 1.99.1). Rust 1.82 does NOT work:
  current crates.io transitive deps require edition 2024. Use
  `rustup toolchain install stable`.
- Node.js 20+ (Tauri CLI only; the frontend has no npm build step).
- Windows: Windows 10 22H2+ or Windows 11 x64, WebView2 Runtime
  (preinstalled on Windows 11 and on updated Windows 10; otherwise
  install the Evergreen WebView2 Runtime from Microsoft), NSIS 3.x.
- Linux/macOS dev: engine + bridge only. Tauri and NSIS are Windows
  build steps and are not expected to run here.

## Reproducible commands

Engine + bridge (any OS with Rust):

```bash
cargo test -p fetchforge-engine
cargo build --release -p fetchforge-engine -p fetchforge-bridge
```

Windows app + installer (on Windows, from repo root):

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-windows.ps1
# Outputs: installer/FetchForge-Setup-0.1.0-x64.exe
#          dist/FetchForge-portable-x64.zip
```

Or via GitHub Actions: `.github/workflows/windows-build.yml`
(`windows-2022` runner, uploads both artefacts).

## Signing

The installer is **not signed** in v0.1.0. No certificate was
available, and none is claimed. To sign: obtain a code-signing
certificate, keep its private key out of source control, and sign both
`FetchForge.exe` and the NSIS output with `signtool` before release,
then verify with `signtool verify /pa`. Until that is done, Windows
SmartScreen will warn on first run — that is expected for an unsigned
build and must not be worked around by asking users to disable
SmartScreen.
